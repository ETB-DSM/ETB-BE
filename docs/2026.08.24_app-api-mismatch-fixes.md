# 앱-서버 API 불일치 수정

## 배경

앱팀이 보고한 불일치 3건을 서버 기준으로 수정한다.

---

## 변경 1: POST /api/v1/auth/refresh — refreshToken 함께 반환

### 현황

| 구분 | 내용 |
|------|------|
| Service 인터페이스 | `Refresh(...) (string, error)` → accessToken 문자열만 반환 |
| Handler | `gin.H{"accessToken": accessToken}` 만 응답 |
| 앱 기대 | `accessToken` + `refreshToken` 둘 다 필요 |

### 수정 내용

- `internal/service/auth.go`
  - `AuthService.Refresh` 시그니처: `(string, error)` → `(domain.TokenResponse, error)`
  - 구현체: `generateAccessToken` 대신 `issueTokens` 호출 (refresh token rotation 포함)
- `internal/handler/auth.go`
  - `h.svc.Refresh(...)` 결과를 `domain.TokenResponse` 로 받아 그대로 응답

### 응답 형태 (수정 후)

```json
{ "accessToken": "...", "refreshToken": "..." }
```

## 변경 2: POST /api/v1/navigation/sessions — 선택적 필드 처리

### 현황

| 필드 | DB | Domain binding | 앱 전송 여부 |
|------|----|----------------|-------------|
| deviceId | NOT NULL FK | required | ✗ |
| destinationId | NOT NULL FK | required | ✓ |
| startLatitude | NOT NULL | required | ✗ |
| startLongitude | NOT NULL | required | ✗ |

### 수정 내용

#### DB 마이그레이션 (000013)
```sql
ALTER TABLE navigation_sessions ALTER COLUMN device_id DROP NOT NULL;
ALTER TABLE navigation_sessions ALTER COLUMN start_latitude DROP NOT NULL;
ALTER TABLE navigation_sessions ALTER COLUMN start_longitude DROP NOT NULL;
```

#### sqlc.yaml
nullable uuid, float8 override 추가:
```yaml
- db_type: "uuid"
  nullable: true
  go_type: "*string"
- db_type: "float8"
  nullable: true
  go_type: "*float64"
```

#### domain/navigation.go
```go
type CreateSessionRequest struct {
    DeviceID       *string  `json:"deviceId"`
    DestinationID  string   `json:"destinationId" binding:"required"`
    StartLatitude  *float64 `json:"startLatitude"`
    StartLongitude *float64 `json:"startLongitude"`
}

type SessionResponse struct {
    SessionID      string   `json:"sessionId"`
    Status         string   `json:"status"`
    StartLatitude  *float64 `json:"startLatitude,omitempty"`
    StartLongitude *float64 `json:"startLongitude,omitempty"`
    CreatedAt      string   `json:"createdAt"`
}
```

#### make sqlc 재생성 후 service/navigation.go 업데이트

## 변경 3: 응답 래퍼 제거

### 현황

서버가 모든 성공 응답을 `{ "success": true, "data": { ... } }` 로 감쌈.  
앱은 래퍼 없이 루트 레벨에서 직접 파싱.

### 수정 내용

`domain/response.go` — `OK` 함수가 data를 직접 JSON으로 반환:

```go
func OK(c *gin.Context, status int, data interface{}) {
    c.JSON(status, data)
}
```

에러 응답은 `{ "message": "...", "errorCode": "..." }` 로 유지 (success 필드 제거).

### 영향 범위
- 모든 엔드포인트 성공 응답 포맷 변경
- 에러 응답은 기존 구조 유지 (HTTP 상태 코드로 성공/실패 구분)
