## 2. 핵심 설계 결정

### 2-1. API 표면 이중화

두 종류의 클라이언트가 존재하므로 prefix를 분리한다.

```
/api/v1/...   ← App (JWT 인증 필수)
/api/...      ← Embedded Device (userId body 파라미터 기반, 인증 없음)
```

Orange Pi는 JWT를 발급받지 않으며, 요청 body에 `userId`를 담아 서버가 users 테이블에서 존재를 확인한다.

### 2-2. User 모델

Embedded의 user register(`userId, name, guardianName, guardianPhone, deviceId`)는 기존 email 기반 users 테이블과 모델이 다르다.

**결정:** users 테이블에 `external_id TEXT UNIQUE` 컬럼을 추가하지 않고, **별도 경량 테이블 `embedded_users`를 생성**한다.

- App 로그인 사용자: `users` 테이블 (UUID PK, email, JWT)
- Embedded 등록 사용자: `embedded_users` 테이블 (user_id TEXT PK, name, guardian_name, guardian_phone, device_id)

Orange Pi의 모든 요청에서 `userId`는 `embedded_users.user_id`를 참조한다.

### 2-3. 응답 포맷

Embedded API 명세서의 응답 예시는 `{"status": "CREATED", "message": "...", "data": {...}}` 형태이나, 현재 구현의 `{"success": true, "data": {...}}` 포맷을 유지한다. 경진대회 범위 내에서 두 포맷을 통일하는 것이 더 단순하며, Orange Pi 측 파싱 로직도 단순해진다.

### 2-4. SOS sentToGuardian

현재 구현에서 보호자 SMS/알림 발송 로직이 없다. `sentToGuardian`은 **항상 false를 반환**하며, 실제 알림 발송은 추후 확장 항목으로 남긴다.

### 2-5. 길안내 명령 조회 (BE-008)

Orange Pi가 polling으로 최신 action을 가져가는 엔드포인트가 필요하다.
`GET /api/navigation/sessions/{sessionId}/instruction` — Embedded API 표면에 추가.

## 3. DB 변경 사항

### 신규 테이블 (마이그레이션)

#### 000007_create_embedded_users
```sql
CREATE TABLE embedded_users (
    user_id      TEXT PRIMARY KEY,
    name         TEXT NOT NULL,
    guardian_name  TEXT NOT NULL,
    guardian_phone TEXT NOT NULL,
    device_id    TEXT NOT NULL UNIQUE,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

#### 000008_create_locations
```sql
CREATE TABLE locations (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id    TEXT NOT NULL REFERENCES embedded_users(user_id) ON DELETE CASCADE,
    device_id  TEXT NOT NULL,
    latitude   DOUBLE PRECISION NOT NULL,
    longitude  DOUBLE PRECISION NOT NULL,
    recorded_at TIMESTAMPTZ NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

#### 000009_create_device_status
```sql
CREATE TABLE device_status (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id   TEXT NOT NULL,
    battery     INT NOT NULL,
    lidar_ok    BOOL NOT NULL DEFAULT TRUE,
    camera_ok   BOOL NOT NULL DEFAULT TRUE,
    gps_ok      BOOL NOT NULL DEFAULT TRUE,
    network_ok  BOOL NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX ON device_status(device_id, created_at DESC);
```

#### 000010_create_navigation_sessions
```sql
CREATE TABLE navigation_sessions (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id        UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    device_id      UUID NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    destination_id UUID NOT NULL REFERENCES destinations(id) ON DELETE CASCADE,
    status         TEXT NOT NULL DEFAULT 'active',  -- active|paused|arrived|canceled|error
    start_latitude  DOUBLE PRECISION NOT NULL,
    start_longitude DOUBLE PRECISION NOT NULL,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

#### 000011_create_navigation_instructions
```sql
CREATE TABLE navigation_instructions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id      UUID NOT NULL REFERENCES navigation_sessions(id) ON DELETE CASCADE,
    action          TEXT NOT NULL,  -- straight|prepare_left|left|prepare_right|right|arrived|reroute
    distance_meters INT,
    message         TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX ON navigation_instructions(session_id, created_at DESC);
```

### 기존 테이블 변경

#### sos_events — battery 컬럼 추가
```sql
ALTER TABLE sos_events ADD COLUMN battery INT;
ALTER TABLE sos_events ADD COLUMN sent_to_guardian BOOL NOT NULL DEFAULT FALSE;
```

## 4. 신규/변경 API 목록

### 4-1. Embedded API (`/api/...`, 인증 없음)

| Method | 경로 | 설명 | Request Body |
|--------|------|------|--------------|
| POST | `/api/users` | Embedded 사용자 등록 | userId, name, guardianName, guardianPhone, deviceId |
| GET | `/api/users/:userId` | 사용자 조회 | - |

| GET | `/api/destinations` | 목적지 목록 (userId 기반) | query: userId |
| POST | `/api/location` | 위치 저장 | userId, deviceId, latitude, longitude, timestamp |
| POST | `/api/ocr/results` | OCR 결과 저장 | userId, destinationId, recognizedText, targetText, confidence, matched |
| POST | `/api/sos` | SOS 요청 | userId, deviceId, eventType, latitude, longitude, battery, timestamp |
| POST | `/api/device/status` | 디바이스 상태 업데이트 | deviceId, battery, lidarOk, cameraOk, gpsOk, networkOk |
| GET | `/api/device/status/:deviceId` | 최신 디바이스 상태 조회 | - |
| GET | `/api/navigation/sessions/:sessionId/instruction` | 최신 길안내 명령 조회 (Orange Pi polling) | - |

### 4-2. App API (`/api/v1/...`, JWT 필수) — 신규

| Method | 경로 | 설명 | Request Body |
|--------|------|------|--------------|
| POST | `/api/v1/navigation/sessions` | 길안내 세션 생성 | deviceId, destinationId, startLatitude, startLongitude |
| POST | `/api/v1/navigation/sessions/:sessionId/instructions` | 길안내 명령 저장 | action, distanceMeters, message |
| PATCH | `/api/v1/navigation/sessions/:sessionId/status` | 세션 상태 변경 | status, reason |

### 4-3. 기존 App API 변경사항 없음

기존 `/api/v1/devices`, `/api/v1/guardians`, `/api/v1/destinations`, `/api/v1/sos`, `/api/v1/auth/...` 등은 그대로 유지.

## 6. 데이터 흐름

### 길안내 플로우 (App ↔ Server ↔ Orange Pi)

```
1. App: POST /api/v1/navigation/sessions
   → server: navigation_sessions 생성 (status=active)
   → response: sessionId

2. App: 위치 업데이트 수신 (Orange Pi가 POST /api/location으로 전송)
   → App이 서버에서 위치를 polling하거나 WebSocket으로 수신
   → App: action 계산 (straight / left / right / arrived)

3. App: POST /api/v1/navigation/sessions/:id/instructions
   → server: navigation_instructions 저장

4. Orange Pi: GET /api/navigation/sessions/:id/instruction (polling)
   → server: 최신 instruction 반환
   → Orange Pi: 음성 안내 출력

5. App: PATCH /api/v1/navigation/sessions/:id/status (arrived or canceled)
   → server: session status 변경
```

### SOS 플로우

```
Orange Pi: POST /api/sos (userId, deviceId, eventType, latitude, longitude, battery, timestamp)
→ server: sos_events 저장 (battery, sent_to_guardian=false)
→ response: { sosId, sentToGuardian: false }
```
