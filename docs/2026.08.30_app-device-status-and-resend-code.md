## 1. 앱용 디바이스 상태 조회 — `GET /api/v1/devices/:deviceId/status`

### 현재 상태
- `internal/handler/device_status.go`의 `Get`은 이미 존재하지만 `/api/device/status/:deviceId` (Embedded, JWT 없음, 소유권 검증 없음) 에만 연결돼 있다.
- 앱은 JWT로 인증하므로 같은 핸들러를 그대로 노출하면 다른 유저의 기기 상태도 조회 가능해진다 → **소유권 검증이 필요**.

### 변경 사항

**`internal/service/device_status.go`**
```go
type DeviceStatusService interface {
    Update(ctx context.Context, req domain.UpdateDeviceStatusRequest) (domain.DeviceStatusResponse, error)
    Get(ctx context.Context, deviceID string) (domain.DeviceStatusResponse, error)
    GetForUser(ctx context.Context, userID, deviceID string) (domain.DeviceStatusResponse, error) // 신규
}
```
`GetForUser`는 `repo.GetDevice(ctx, GetDeviceParams{ID: deviceID, UserID: userID})`로 소유권을 먼저 확인(실패 시 `domain.ErrNotFound`, 기존 `device.go`의 `Delete`와 동일 패턴)한 뒤 기존 `Get` 로직(`GetLatestDeviceStatus`)을 재사용한다.

**`internal/handler/device_status.go`**
```go
func (h *DeviceStatusHandler) GetForUser(c *gin.Context) {
    userID := c.GetString("userId")
    deviceID := c.Param("deviceId")
    res, err := h.svc.GetForUser(c.Request.Context(), userID, deviceID)
    if err != nil {
        domain.Fail(c, toAppErr(err))
        return
    }
    domain.OK(c, http.StatusOK, res)
}
```

**`cmd/server/main.go`** — `authRequired` 그룹에 추가
```go
authRequired.GET("/devices/:deviceId/status", deviceStatusH.GetForUser)
```

**`api.md`** — 디바이스 섹션에 항목 추가 (에러: `NOT_FOUND` — 기기가 없거나 본인 소유가 아니거나, 아직 상태 보고가 없는 경우 모두 동일하게 404로 응답 — 기존 `Get`과 동일한 정책).

### 응답 포맷 (기존 `DeviceStatusResponse` 재사용, 변경 없음)
```json
{
  "deviceId": "aicane_001",
  "battery": 78,
  "lidarOk": true,
  "cameraOk": true,
  "gpsOk": true,
  "networkOk": true,
  "createdAt": "2026-08-30T09:00:00Z"
}
```

## 2. 이메일 인증 코드 재전송 — `POST /api/v1/auth/resend-code`

### 현재 상태
`AuthService.Signup`이 유저 생성 + 코드 발송을 한 번에 처리한다. 재전송 시에는 유저를 다시 만들 수 없으므로(이미 존재 → `ErrConflict`) 별도 엔드포인트가 필요하다.

### 변경 사항

**`internal/domain/auth.go`(신규 요청 타입)**
```go
type ResendCodeRequest struct {
    Email string `json:"email" binding:"required,email"`
}
```

**`internal/domain/errors.go`** — 에러 코드 추가
```go
ErrEmailAlreadyVerified = newErr(http.StatusConflict, "EMAIL_ALREADY_VERIFIED", "email already verified")
```

**`internal/service/auth.go`**
- `Signup` 내부의 "코드 생성 → Redis 저장 → 메일 발송" 블록을 `sendVerificationCode(ctx, email string) error` private 메서드로 추출해 `Signup`과 신규 `ResendCode`가 공유한다.
```go
type AuthService interface {
    // ... 기존 메서드
    ResendCode(ctx context.Context, email string) error // 신규
}

func (s *authService) ResendCode(ctx context.Context, email string) error {
    user, err := s.repo.GetUserByEmail(ctx, email)
    if err != nil {
        return domain.ErrNotFound
    }
    if user.EmailVerified {
        return domain.ErrEmailAlreadyVerified
    }
    return s.sendVerificationCode(ctx, email)
}
```

**`internal/handler/auth.go`**
```go
func (h *AuthHandler) ResendCode(c *gin.Context) {
    var req domain.ResendCodeRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        domain.Fail(c, domain.ErrInvalidRequest)
        return
    }
    if err := h.svc.ResendCode(c.Request.Context(), req.Email); err != nil {
        domain.Fail(c, toAppErr(err))
        return
    }
    domain.OK(c, http.StatusOK, gin.H{"message": "인증 코드가 재전송되었습니다."})
}
```

**`cmd/server/main.go`** — `auth` 그룹에 추가 (JWT 불필요, signup과 동일한 위치)
```go
auth.POST("/resend-code", authH.ResendCode)
```

**`api.md`** — 인증 섹션에 항목 + 에러 코드 표에 `EMAIL_ALREADY_VERIFIED` 행 추가.

### 레이트 리밋
기존 `signup`에도 레이트 리밋이 없으므로 이번 작업 범위에서도 추가하지 않는다 (일관성 유지). 필요하면 별도 작업으로 분리.
