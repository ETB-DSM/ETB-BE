# Device API Key 인증 설계

**날짜:** 2026-08-25
**작업:** feat/device-api-key

---

## 문제

Orange Pi가 `/api/v1/sos` (JWT 필요) 를 호출해 `UNAUTHORIZED` 반환.
현재 `/api/sos` (`CreateEmbedded`) 는 body에 `userId`, `deviceId` 를 평문으로 넣는 방식이라
누구나 유효한 ID만 알면 SOS를 위조 가능.

---

## 목표

- Orange Pi가 야외에서 인터넷 불안정한 환경에서도 SOS 전송 가능
- 기기별 고유 API Key를 한 번 받으면 만료 없이 재사용
- `userId`, `deviceId` 를 body에 직접 노출하지 않음

---

## 결정: 기기별 정적 API Key

| 특성 | 내용 |
|------|------|
| 키 형식 | 32바이트 crypto/rand → 64자 hex 문자열 |
| 발급 시점 | 앱에서 `POST /api/v1/devices` 호출 시 자동 생성 |
| 전달 방법 | Response body에 `apiKey` 포함, Orange Pi config에 저장 |
| 인증 방법 | `X-Device-Key: <apiKey>` 헤더 |
| 만료 | 없음 (장치 삭제 시 키도 제거) |

---

## 변경 파일

### 1. Migration
`000014_add_api_key_to_devices`
- `devices` 테이블에 `api_key TEXT UNIQUE NOT NULL` 추가
- 기존 row 는 `uuid_generate_v4()` 로 backfill

### 2. query/device.sql
- `CreateDevice`: `api_key` 컬럼 포함하도록 수정
- `GetDeviceByAPIKey` 쿼리 추가

### 3. sqlc 재생성
→ `internal/repository/sqlc/device.sql.go`, `models.go` 갱신

### 4. domain/device.go
- `DeviceResponse` 에 `APIKey string` 추가

### 5. service/device.go
- `Create()` 에서 32바이트 random hex 생성 후 repo에 전달
- `toDeviceResponse()` 에 `APIKey` 매핑

### 6. middleware/device_auth.go (신규)
- `X-Device-Key` 헤더 읽기
- `GetDeviceByAPIKey(ctx, key)` 호출
- context에 `deviceId`, `userId` set

### 7. domain/sos.go
- `EmbeddedCreateSosRequest` 에서 `UserID`, `DeviceID` 제거
  (미들웨어가 context에 set하므로 body 불필요)

### 8. service/sos.go
- `CreateEmbedded(ctx, userID, deviceID string, req)` 로 시그니처 변경
- `embedded_user` 조회 제거 (device key 미들웨어가 이미 검증)

### 9. handler/sos.go
- `CreateEmbedded()` 에서 context의 `userId`, `deviceId` 추출 후 service 호출

### 10. main.go
- `/api/sos` 라우트에 `middleware.DeviceKeyAuth(q)` 추가

### 11. api.md
- `POST /api/sos` 스펙 갱신 (헤더 추가, body 필드 제거)
- `POST /api/v1/devices` 응답에 `apiKey` 추가

## API Key 흐름

```
[앱, Wi-Fi 연결 상태]
  POST /api/v1/devices
  Response: { deviceId, name, isActive, apiKey, createdAt }
  → 사용자가 apiKey를 Orange Pi에 입력

[Orange Pi, 야외]
  POST /api/sos
  Header: X-Device-Key: <apiKey>
  Body: { eventType, latitude, longitude, battery }
  → 서버가 devices 테이블에서 apiKey 검색
  → device.userId + device.id 추출
  → sos_events 생성
```

## SOS 요청/응답 변경

**Before:**
```json
{
  "userId": "...",
  "deviceId": "...",
  "eventType": "fall",
  "latitude": 37.12,
  "longitude": 127.56,
  "battery": 80
}
```

**After (Header 방식):**
```
X-Device-Key: <api_key>
```
```json
{
  "eventType": "fall",
  "latitude": 37.12,
  "longitude": 127.56,
  "battery": 80
}
```
